# Phase 1 area baseline

Measured, not estimated. `make area` synthesises every module in `rtl/` as its
own top with Yosys (`synth -flatten`, then `dfflibmap` + `abc` onto the sky130
high-density liberty set) and reports the area Yosys maps it onto.

- Liberty: `third_party/sky130_fd_sc_hd__tt_025C_1v80.lib`
- Cell area in um^2; the liberty areas are for a single drive-strength cell, so
  these are the standard-cell areas before placement and routing.
- This is combinational plus sequential area of the RTL as written. It is **not**
  a silicon area estimate: no floorplan, no routing, no fill, no macro placement.

## Reading it

- **`core` is the whole design**: 8698 cells, 81732 um^2, of which 39538 um^2 (48%)
  is sequential. Its area is the sum of the twelve blocks plus its own glue, so
  it is the only row that matters for the phase-10 budget.
- The twelve blocks sum to 76899 um^2, which is 94% of `core`. The remainder is
  the pipeline registers and the redirect/stall logic in `core` itself.
- **`regfile` is the single largest block at 51516 um^2 (63% of the core)** -
  32 x 32 bits of storage mapped naively to flip-flops. On a real flow this is
  the obvious first target for replacement by a compiler-generated or memory
  mapped register file; it is roughly half the design's area today.
- `ex_stage` (9978 um^2) is next, and `alu` inside it is 5781 um^2 of that.

## Caveats for the area budget

1. These numbers exclude SRAM macros entirely. Phase 1 has no memory macro and
   no cache; the eventual instruction and data memories will dominate the
   floorplan, and no amount of register-file optimisation changes that.
2. Nothing here has been placed or routed. A real core will grow with routing
   congestion, and the growth is not proportional.
3. `abc` is doing generic mapping with no timing constraint, so it makes no
   effort to trade area against a clock period. A timing-driven run will be
   larger.
4. The liberty set is a nominal corner with no derating, no wire load, and no
   clock-tree contribution.

Treat this as the **first real data point**, and as evidence that register-file
area reduction is worth pursuing before the floorplan is fixed - not as a
silicon prediction.
